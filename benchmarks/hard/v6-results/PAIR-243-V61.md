## Class lesson (published with the same weight as a win)

A loop is a trajectory, not a cell: ANY context change at the first read re-rolls every
downstream turn, so prevention nudges trade target-cell conversions for non-target-cell
re-draws at the same lottery rate. Measured exchange here: 2 target cells won (100% of live
targets), 2 of 16 non-target loop cells lost (12.5%) — net zero on the pool, +9.5% energy.
This is the loop-pool instance of the bank-wide selection rule (lottery classes are fixed by
SELECTION, not nudges, validated on H 2.9 and D 2.11): the next loop mechanism must key on the
failure signature AFTER a full attempt — the 2.11 loop best-of-2 is on the line but its trigger
notes (`status_filter_violation`, `plans_dangerous_action`) do not cover the
banned-attempt/format-dead family this pair mapped, so the loop losses remain open as a
SELECTION target, not a nudge target. A further prevention-style nudge on loop cells is
considered closed by this measurement.
