## Verdict: 0.0.2.30 is a negative result, and the regression is named

- Mean over three matched seeds: 60.3 (0.0.2.29) → 59.0 (0.0.2.30). Paired sign tests per seed: 0W/1L,
  3W/4L, 2W/4L — no effect, if anything negative.
- Flip count got worse: 8 → 12 unstable cells.
- The guarantee fired on 9 of 231 rows (`contour:v230_contract_reask_json_object` + `_reask_ok`), so it is
  live code — it just does not help, and in one cell it clearly hurt: `A-ex6-07` went 3/3 → 0/3.

Mechanism of the harm, from the ledger: for category A the bank contract is `FIELD: value` lines, not a JSON
object. The 0.0.2.30 shape detector asks for a JSON object in category A, judged a passing field-line answer
"collapsed", took a fresh sample to replace it, and the fresh sample answered with the wrong fields. A shape
enforcer that misreads the contract does not just fail to help — it can overwrite a correct answer with a
coin flip.

Decision: keep the code and the tests, but the mechanism is NOT adopted as an improvement. Before any retry
it needs the required shape read from the task's own prompt (the 0.0.2.29 approach) instead of a category
heuristic, and it must never replace an answer that the frozen scorer can already parse. The retry would be
a new stamp and a new paired arm, with this one as the control.

What survives from this cycle: the corrected stability map (`UNSTABLE-CELLS-V61.md`), the six contour seeds,
the five bare-basalt seeds, and the fact that the malformed-stamp guard killed a first attempt of this same
experiment at zero serve cost when a runner script wrote `0.0.2.229` instead of `0.0.2.29`.
