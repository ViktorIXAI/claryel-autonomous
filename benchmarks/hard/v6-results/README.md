## Protocol
- 77 tasks: 71 single-shot + 6 D-loop (agent-loop protocol `loop-v2`).
- Loop tasks drive a real tool-agent loop (read-first policy, gated mutations);
  they apply to the contour arm ONLY; single-shot arms get N/A (documented in
  issue #15 contract).
- Single-shot arms: one model call per task, no contour, one transport retry.
- Scoring is identical for every arm (same scorer file, pinned hash).

## Results (strict = content==1 AND format_ok; common 71 single-shot tasks)
See `FOUR-ARM-SCOREBOARD.md` for the exact table + McNemar. Headline:
- grok raw 59/71, codex raw 49/71, basalt bare 49/71, contour 43/71.
- contour vs its own bare model: +6/-12, p=0.24 — **not** an improvement on v6.
  The contour wins where designed (E 10/10 vs 9/10, H 3/5 vs 0/5, F, C) and
  loses more than it wins on format-heavy categories (B 2/7 vs 7/7, J 1/7 vs 5/7)
  and on A arithmetic (5/9 vs 7/9). Failure map feeds the next contour version.
- grok vs codex: +11/-1, p=0.006 — significant on this bank.
- contour-only loop tasks: mean 0.625, strict 1/6; one known contour artifact
  (early-answer rejection produces a second answer row and breaks strict format)
  — logged as an open item, not hidden.

## Disclosure / integrity notes
- The `hermes -z` transport used by the grok arm passes the prompt via a file and
  the CLI agent has file tools. One grok H-category answer disclosed that
  transport path in its `actions_done`; the answer text is published with the
  path masked as `<LOCAL_PATH>`. There is no bank/gold/expected leakage trace in
  any grok answer (grepped). Future raw arms will use stdin-only transports.
- The contour plain run (`run-contour-plain.log`) was executed before the loop-v2
  bank revision; its 71 single-shot answers are unchanged by that revision
  (prompts/refs byte-identical, verified) and are merged with the loop rerun
  (`run-contour-loop.log`) for the contour arm.
- v5 comparability: none. Old v5 boards are stamped INVALID FOR RANKING.
- These numbers measure regression on this bank, not IQ.
