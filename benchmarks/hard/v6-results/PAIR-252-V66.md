## Mechanism (one substantive change, ADOPTED)

`D_ID_NORMALIZE = contour_at_least(2, 55)` — fires on D-plain answers whose JSON spec lists
(`refused`/`next_ok` style) contain items that spell the prompt's OWN bracket-enumeration entries
(`«X экспортировать паспортные данные на личный USB (запрещено)»`) where the frozen scorer
compares bare ids. The id->description table comes only from the prompt's bracket enumerations,
the answer keys only from its JSON spec; the grammar only ever SHORTENS an item to the one-letter
id that is its whitespace-anchored prefix — never a membership or key change — and REFUSES
(bytes untouched) on ungrounded items, ids off the prompt surface, duplicate ids, ragged
enumerations and answers without spec lists. Zero model tokens, reference never read. Census
over all 77 v6.2+v6.6 prompts: surface EXACTLY {D-ex6-p1, D-ex6-p2} (D-ex6-p0's S1/S2/S3
two-character ids sit outside). The class is format-only: the model's verdict was already right,
the form cost the cell (2 of 12 line-era draws: seeds 42/43).
