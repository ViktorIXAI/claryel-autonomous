# Evaluation-system roadmap for the v6.2 measurement stack

Owner directive, 2026-11-07: the tests and the scoring system are maintained like code — every
element is versioned, corrections arrive as a new version plus a re-score, and nobody waits for an
owner decision to make them. This file is the queue; each item is a release with its own contract
test, changelog and re-score pass.

## Why the stack needs versioning (measured, not theoretical)

- Two bank tasks are wrong in a way that silently zeroed correct answers: `A-ex6-03` (gold computed
  from a base of 5700 that the prompt never prints; **0 of 89 published rows pass it, across every
  arm including both raw brains**) and `C-ex6-02` (all four shipped snippets print `[1, 2, 3]` on
  CPython while the gold demands `[C]`). See `bank-defect-v61-queue.md`. A frozen bank turned a
  benchmark bug into a model penalty.
- Three of thirteen contour pairs bought nothing because the control line had already fixed the
  target cell (`0.0.2.33`, `0.0.2.38`, `0.0.2.41` = UNMEASURED): six arms of serve time each, with
  no live target. The evaluation system, not the contour, is at fault: no pre-launch measurability
  gate existed.
- The same stamp over the same three seeds differs on **12 of 231 cells (5.2 %)** and in mean by
  ~1.4 cells, so any delta under ~2 cells at three seeds is unresolvable. That floor is now
  published; it is not yet used to size runs in advance.

## R1 — bank v6.2 (`bank-hard-v6.2.json`) — in progress

- Fix the three queued defects with re-computed golds and an arithmetic/re-execution proof per
  change; leave v6.1 bytes untouched; publish `bank-defect-v62-changelog.md` listing every changed
  byte and why.
- Every task gains a `derivation` field: the code or arithmetic chain that produces its gold from
  the text the model actually sees. Tasks with no mechanical derivation are explicitly typed
  `judgment` and scored under a written rubric contract, not pretending to be objective.
- CI re-derives every gold from `derivation`. A task whose stated rules and gold disagree fails CI —
  that is exactly how `A-ex6-03` and `C-ex6-02` would have been caught before they cost 89 rows.

## R2 — scorer contract versioning (`parb_check_v6_2.py`, `SCORER_CONTRACT`)

- One contract module and one contract test per version; the constant is stamped into every scored
  row, every scoreboard table and every run record, so a number can never be read without its
  scorer identity (the four-arm/scoreboard mismatch in `FOUR-ARM-SCOREBOARD` was a contract drift).
- Split the score into two published axes instead of one blended number: answer quality and
  protocol compliance. In loop-D, a correct final answer after a banned tool attempt is currently
  capped at 0.3/0.7 in one number, which mixes "the model answered correctly" with "the trajectory
  violated policy" and hides both.
- Typed failure codes instead of free-text reasons (already partly in place): `set_mismatch`,
  `order_partial`, `fields_mismatch`, `unknown_missing`, `banned_attempt`, `engine_stalled`. Typed
  codes are what makes the instability map and the defect queue automatic instead of manual.

## R3 — measurability gate before any pair launches

- Before spending six arms on a pair, the harness replays published bytes and answers three
  questions mechanically: does the target mechanism fire on at least one live cell; does the
  control line actually fail that cell; how many seeds are needed to resolve the expected effect
  above the published noise floor. If the answer is no, the pair does not launch — the stamp is
  frozen and the reason published. This turns the three UNMEASURED pairs into a pre-launch refusal.

## R4 — statistics promoted from prose to artifacts

- Pre-registration stays, but the numbers themselves go into machine-readable files (per-cell pass
  matrices, sign-test tables, bootstrap CIs) so any future claim is regenerated by
  `scripts/` rather than retyped. Regeneration already exists for cadence
  (`scripts/cadence240_cloud_v61.py`); extend it to pairs and bands.
- Headline metric becomes score per unit energy as well as score: the contour's current
  0.094 Wh/answer against 0.31 Wh/answer for the bare model is a first-class result, not a footnote.

## R5 — full-stack identity per run

- `versions/MEASUREMENT-STACK.md` plus a `stack.json` inside every run directory: bank version +
  sha16, scorer contract version, seed-protocol version, contour stamp, harness commit, endpoint
  model id. CI refuses any results directory without it. Any number in any table that cannot name
  its stack is invalid by definition.

## R6 — leakage and contamination checks extended

- Existing: zero answer-bytes references to bank/gold/paths in published artifacts.
- Add: gold-leakage scan in the other direction (does a prompt text leak the reference value or the
  graded keyword), which is what makes the `judgment` typing honest, plus a per-category check that
  a scorer keyword never appears in a prompt (the shape-guarantee lesson from `0.0.2.30`).

## Release order and effect

R1 then R2 (they must land together: a new bank without a versioned scorer re-creates the drift),
R3 and R5 next because they are cheap and prevent wasted serve time, R4 and R6 as the steady-state
hygiene. After R1+R2 the four arms are re-run on v6.2 and every published arm is re-scored, so the
comparison table changes only where the correction was proven — and the delta table says exactly
where.
