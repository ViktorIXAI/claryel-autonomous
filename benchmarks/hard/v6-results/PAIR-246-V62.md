## Mechanism (one substantive change)

The adopted 2.13 C best-of-2 selection re-draws a failed C task once when the scorer note belongs to
the `missed_options` family. The frozen v6.2 C scorer never emits `missed_options` for C — its set
note is the space-parameterized `set_mismatch got=[...] want=[...]` — so the adopted trigger has a
structural coverage gap on this bank (pair-243/244 note-family lesson, third occurrence).
`0.0.2.47` adds a second trigger of the same monotone recipe: on a first-draw `set_mismatch` stem
(split at first `:` or whitespace; `id_set_mismatch` stays out) the task is re-drawn once at a
distinct offset `seed + 17491` (C 2.13 uses 5309; D uses 4096/8117/12289) and the retry is adopted
only if strictly better (`content + bool(format_ok)`). `missed_options` keeps precedence for offset
and event naming; at most one C retry per task; the call site is `cat == "C"`, so H/D rows that can
carry the same note string are structurally unreachable (pair-245 H-parity lesson).
Events: `contour:v47_c_best2_set_fired` / `fix:v47_c_best2_set_win`.
Contract: `harness/gate_v61_c_best2_set_test.py` (40 checks, incl. real `run_one` drives over the
live 2.29 coverage protocol at both stamps and H-parity), enrolled in CI in the same commit.
