# Public benchmark percent digest

One row per scored arm, newest first, written by `scripts/pub_bench_score.py`. Rows are only comparable when the task-file sha16 and the call parameters match. Deterministic checkers live here; the HumanEval execution checker lives in `scripts/pub_bench_exec.py` (contract `pytest-v2`) and names itself in the call column; an unshipped checker keeps its tasks out of the denominator and says so. Checker contract in force: `pub-checkers-v2` - the scorer refuses to publish while its own self-test fails, and a gold the contract cannot parse is scored as UNSCORED, never guessed. A row re-scored under another contract id is a new row, not an edit.

Supersession pointers (parity shape rule, 2026-11-08; never an edit of old bytes): a contour row whose call column says `ladder rungs 512,1200, enable_thinking off` is a request-shape cost, not a contour effect, and is superseded as a parity row by the matched-shape row (`first rung 1200`) for the same bench and model - gpqa-diamond 46.0 % -> 70.2 %, arc-challenge 94.3 % -> 97.0 %, arc-easy 96.7 % -> 96.3 %, gsm8k-300 96.7 % -> 98.0 %. HumanEval rows labelled `checker pytest-v1` are superseded as verdicts by the `pytest-v2` rows scored from the same stored answer bytes. LiveCodeBench rows labelled `checker lcb-exec-v1` are superseded as verdicts, for all three arms, by the `lcb-exec-v2` rows scored from the same stored answer bytes (2026-11-09 release closing the functional-driver gap: 112-denominator -> 175-denominator, every stdin verdict cell identical under both contracts). IFEval rows keep their published `checker pub-ifeval-v1` verdicts; the 2026-11-10 corrected table under contract `pub-ifeval-v2` (which stops the vendored checker re-drawing the literal `letter` kwarg at random in 2 of 541 cells) lives in `IFEVAL-RESULT.md`, beside the cells it moves. Each `<BENCH>-RESULT.md` carries the dated pointer and the reason.

Tasks-cell convention (pin audit 2026-11-10, no row or byte moved): a tasks cell names the pinned task file, and the two hash conventions in this repo are not interchangeable. Every set prints SHA-256/16 except IFEval, whose published pin `2c672531577dcc33` is the **SHA-1/16** of the same 541 rows (SHA-256/16 `e09a5cab3782ed5b`) - `MANIFEST.json -> benches.ifeval.hash_note` labels both, and `scripts/pub_bench_score.manifest_tasks_cell` reads that pin instead of re-hashing, so one pinned task file can never carry two different tasks cells in this table. The artifact index `benchmarks/public/arms/README.md` now pins both conventions per row and `scripts/pub_arms_index.py --check` fails closed if any pin, line count or sidecar drifts.
