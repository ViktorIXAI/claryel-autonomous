# P3001 full contour sweep — harness v2.1 on the 2013 Xeon box (2026-11-02)

Single-box full-plan pass of the verification-contour harness (`PGR`) against
the production IQ3_S serve on P3001 (NVMe path, `--max-context 32768 --kv
int8 --mmap-experts --spec 4 --mtp rt`, engine 0.1.55 local AVX1 build — see
hardware/inventory/P3001.md). Contour: **v2.1** (`gate_fixers_test` 12/12
pre-launch; smoke subset 2/2 c=1.00 first). Runner on the workstation hit the
box's OpenAI endpoint over LAN; temperature 0.7 as in every series.

## Scope and completeness

188 plan positions = 178 distinct bank tasks (categories A–K: extraction,
finance B/C, agent loops D, cause-analysis E, plan-safety F, document QA G,
uncertainty H, …), each at rep 0 with the series' own gseed. Runner finished
by plan exhaustion (`стоп-причина: нет`), 5,224 s wall (~87 min).

## Findings

**Capacity, not capability (the two G zeros).** `G-ve-13` and `G-ve-14` score
0.167 with `engine_error: HTTP Error 400` after 0.1 s and 0 generated tokens:
their 113,010/113,019-character documents (~30k tokens) exceed this box's
32,768-token context, so serve rejected the prompt outright. Every G task
that fits scores 1.00. Same lesson as the old holdout incident: never publish
a context-overflow as a model failure. On 64k-context boxes these two tasks
score 1.00 in earlier series.

**Weak category: F (plan-safety, 0.70).** Notes are `too_few_safe_steps` —
the contour asks for more safe steps but the box's answers stay short. F is
the next contour hypothesis's target (candidate: a second safe-steps nudge
branch on F modes, per the v1.8 nudge pattern).

**Hardware conclusion.** A 2013 workstation with a local-build engine runs the
full v2.1 contour at 0.972 adjusted mean — 96 % of what the faster fleet boxes
get on the same contour — at ~22 s per harness task. Usable as a third-line
node for agent workloads; document-QA tasks with >25k-token documents need a
bigger-context box.
