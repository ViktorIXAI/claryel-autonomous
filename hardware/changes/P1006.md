## CHG-001 — box first sighted, onboarded, key delivery failure diagnosed (2026-11-13 14:00 UTC, status: closed)

**Contract:** the maintainer names new boxes by fleet ID only. This LAN has no
name service at all (no DNS PTR, no mDNS, no NBNS — hand-built probes come back
silent), so a spoken ID must be matched to a live address by fingerprint, never
by guessing.

**Identification.** Candidate unnamed Ubuntu 24.04 hosts were fingerprinted
(ping TTL, MAC OUI, pre-auth SSH banner, keyscan digests against the known-hosts
store). The ID was confirmed from the box's own console prompt and its wired NIC
MAC, which matched one of the two MSI/Meigao candidates recorded the same day.
The other candidate is still unnamed and untouched.

**Onboarding incident — the failure mode worth recording.** The standard console
block pulls the fleet public key over plain HTTP from the key-server host. That
fetch hung 132 s and failed, but the rest of the block ran: the self-check line
came back `ssh=2 key=0`, i.e. listener up, sudoers up, firewall rule added, and
**no key**. A word-only reading of the self-check ("GOTOVO") reports success on a
box that is unreachable. Cause, measured the same day: on the key-server host the
service answers locally but its own host firewall (default-deny inbound) drops
the key port — proved from a second fleet host, where the connect times out after
~130 s (DROP) instead of being refused (no listener). The service also was not
running at the time of the failed attempt.

**Recovery and verification.** The public key was written inline on the console
instead of fetched (firewall-independent). Verified on the box: exactly one
authorized key, `ssh-keygen -lf` digest matches the fleet key (ED25519). Verified
from the control host: SSH login succeeds and passwordless sudo works
(`sudo -n true` exit 0). Fleet-side: the key-server now runs again on the control
host, and the standing rule is inline key paste unless the firewall rule for the
key port has been opened deliberately.

**State S1 as first sighted** (live reads, no datasheet values): chassis
MSI B550-A PRO (MS-7C56) BIOS `A.F0`; Ryzen 5 5600X 6c/12t, AVX2, no AVX-512;
64 GB DDR4-3200 non-ECC (4x16 GB Samsung `16G3200CL16`); Intel Arc A750 8 GB
(`8086:56a1`, DG2 rev 08) on the open-source stack, no NVIDIA modules; single
Samsung 990 PRO 1 TB NVMe holding root **and** the data tree; container engine
and a Cloudflare token tunnel active; host firewall inactive; graphical target
with a live autologin console session. Passport: hardware/inventory/P1006.md.
