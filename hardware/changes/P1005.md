# Hardware change ledger — P1005 (platform box)

P1005 is a **platform**: the published anchor is the chassis + board
(ASUS Z10PA-U8, LGA2011-3). CPU, RAM, storage and GPU are versioned test
variables — every physical or serving-stack change gets a CHG entry here and a
numbered hardware state in `hardware/inventory/P1005.md`. Benchmark results
published for this box are only valid for the state they were produced under.

## CHG-001 — GPU swap Tesla P100 16 GB → RTX 3060 12 GB (2026-11-02, closed)

Pre-swap state (S1, captured 2026-11-02 before shutdown): GPU `10de:1b87`
Tesla P100-PCIE-16GB, driver 580.196.07, Strata repo v0.2.9 / engine 0.1.55
cuda12; baseline records pinned by reference: results/p1005-speed-records.md
(decode peak 47.2, prefill 294.0) and results/p1005-v21-full.md (v2.1,
2421 pairs).

Post-swap (state S2, 2026-11-03): GPU `10de:2544` GA106 RTX 3060 12288 MiB
(the P100-era onboard ASPEED stays as console GPU; the 3060 has outputs but is
unused for display). Driver branch forced to 615.71.09 (Ubuntu
`nvidia-driver-615`); engine raised to 0.1.56 cuda12. gpu-unlock module
(Zagitta 2.0) installed and verified: `gpu_unlock: unlocked`, both PLM writes
ret=0; card VBIOS power ceiling 187 W pinned via `@reboot sudo nvidia-smi
-pm 1 && -pl 187`.

Before/after (same quickbench ladder 2k/8k/16k, warm, raw model):

| metric | S1 P100 (580) | S2 RTX 3060 (615, 187 W, unlock on) |
|---|---|---|
| decode ladder | 15.6 / 21.6 / 26.5 (cold recipe) — warm records 40.7–47.2 | 31.4 / 45.7 / 46.7 (best pass), repeat passes 25.6–44.5 |
| prefill 16k cold | 294.0 | 371–448 (config-dependent: 448 at 25 GiB resident, 377 at 20 GiB) |
| unlock effect | n/a (Pascal unsupported) | +1.7 % prefill, decode flat — box is RAM-streaming-bound |
| contour v2.2 quick (178 tasks) | — | 0.9759 @170 W pre-unlock / 0.9829 @187 W unlocked (paired 4/4/170 — noise) |

Verdict: on this platform the 3060 moved the prefill ceiling (+30–50 % at
parity decode) but gpu-unlock/power headroom paid ≈0 — the binding term is
DDR4-2133 expert streaming, not tensor issue rate.

## CHG-002 — GPU swap RTX 3060 12 GB → Tesla P100 16 GB (return, 2026-11-03, closed)

Pre-swap snapshot (S2): as above; gpu-unlock package kept but the
`gpu_unlock.targets=` GRUB parameter was removed before power-off so an
unsupported replacement card cannot fail the unlock path on first boot.

Post-swap (state S3): GPU `10de:15f8` Tesla P100-PCIE-16GB (rev a1) — same
model as S1. Driver branch rollback 615 → 580.196.07 (R615 dropped
Maxwell/Pascal support; dkms reinstall on both installed kernels); **module
reloaded live with `modprobe nvidia`, no reboot required**. Power limit
250 W — factory default=min=max for this card, no headroom to set. Engine
unchanged: repo v0.2.10 / 0.1.56 cuda12 (archs include sm_60). keep-up cron
respawned serve unattended (20 GiB resident experts, 983 MiB VRAM free).

Post-swap sanity ladder (warm, same script): decode 27.8 / 37.6 / 43.9 at
2k/8k/16k; prefill 16k 279.4; 52.7 W draw at 55 °C — matches the S1 P100
record band (40.7–43.8 sustained, 294 prefill peak). No regression.

## CHG-003 — P100 firmware GPU-mode switch compute -> graphics (2026-11-03, closed)

Performed on P1005 while the card was installed there, because P3032 (HP
Z220) cannot map the card's default 16 GiB BAR1 (no above-4G aperture;
512 MB sub-4G hole only). `nvflash --gpumode graphics` (nvflash 5.867);
full procedure, before/after BAR measurements and failure records:
`results/p100-gpumode-256mb-bar1.md`. Original firmware saved to a backup
file (sha256 `c9c09173…fe00`, kept private). ECC re-enabled. Card returned
to cold state (machine powered off) for transfer to P3032. P1005-side
consequence: BAR1 16 GiB -> 256 MiB; P1005 is memory-streaming-bound
(CHG-001), so no expected inference impact.
