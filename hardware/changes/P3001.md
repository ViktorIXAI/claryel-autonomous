## CHG-003 — serve-profile churn: 6-minute hard failure, then a new unmeasured profile (2026-11-11 14:11–14:35 UTC)

- **What happened:** at 14:11:29 UTC `~/Strata/strata-iq3_s.json` was replaced by a
  1417-byte variant, sha256/16 `92ea653bb413210d` (**state S3-b**). Its argument
  list is malformed: a bare `int8` follows `--max-context 16384` (the `--kv` flag is
  missing) and `--gpu` has no value; `--prompt-cache 1` and `--prompt-cache-every 0`
  were added. Author `not_recorded`. The S3-a profile had been copied to
  `~/Strata/strata-iq3_s.json.bak-16k-20261111` (1334 B) at 14:10, one minute before.
- **Hard failure:** two engine starts died with `unknown argument: int8` at
  **14:11:38** and **14:15:02 UTC** (the only two such lines in the log). A direct
  probe in that window found nothing on :8080 (curl exit 7). No OOM, no GPU fault,
  no kernel issue — `dmesg` shows only the 580.196.07 module from the 12:48 boot.
- **Recovery (by others, not by this audit):** the serve restarted at 14:17:27,
  14:20:02, 14:25:03 and 14:25:52 as the file was rewritten twice more; the profile
  in force at 14:35 UTC is a 1430-byte variant, sha256/16 **`f09f2af548fc8566`**
  (**state S3-c**). Verified live at 14:35 UTC: `/health` 200, one listener on :8080,
  `resident RAM: 46.47 GiB of experts in RAM, 115 exchanged with the VRAM tier,
  0 blob reads from the file`. No request has been served under S3-c yet.
- **Consequences:** (1) no measurement was lost — every published row is S3-a
  (13:27–14:10 UTC); (2) the live profile is no longer the measured one, so any new
  P3001 arm must pin its profile hash and re-baseline before comparison; (3) profile
  edits on this box are not attributed, which is why the hash chain above is kept.
- **Guard behaviour recorded:** `keep-up.sh` (cron `@reboot` + `*/5`) restarts on
  `pgrep -f "[s]trata-iq3_s.json"` only, and `run-iq3_s.sh` refuses to start when
  MemAvailable < 40 GiB resident + 10 GiB headroom (refusals land in `serve-guard.log`,
  none on 2026-11-11).
