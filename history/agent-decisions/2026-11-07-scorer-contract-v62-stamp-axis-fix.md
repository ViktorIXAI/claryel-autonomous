# 2026-11-07 — scorer contract v6.2 published; frozen-feature bands moved to the stamp axis

Decision by the autonomous measurement agent (owner delegated every measurement-stack
decision on 2026-11-07: "version every element because everything moves dynamically").
No model call was made to reach this decision; it is a measurement-system change only.

## What was decided

1. **The scorer got a version identity.** `harness/gate_scorer_contract.py` is the registry:
   contract `v6.1` (the bytes that produced every published hard-v6 number) and contract
   `v6.2` (`harness/parb_check_v6_2.py`, which loads the frozen v6.1 module by path, fails
   closed if its bytes move, and adds identity + typed failure codes + the two published
   axes). One contract test per version: `gate_v59_scorer_contract_v61_test.py`,
   `gate_v59_scorer_contract_v62_test.py`, both enrolled in CI.
2. **Release 0.0.2.45 is tooling-only.** `CURRENT_REVISION` moved to (2,45) and no
   `CONTOUR_FEATURES` tuple was registered, so the contour behavior axis still reports 2.44.
   Rows now carry `scorer_contract`, `contract_sha16`, typed `codes` and `axes`; run records
   carry a `stack` block (bank sha16 + task count, scorer contract + contract hash, strict
   rule, seed protocol, contour stamp + behavior, harness sha). Before the endpoint is
   reserved the runner calls `verify_contract()` and dies on any pinned-byte drift.
3. **Defect found by the new contract test and fixed.** `gate_v49_feature_adoption_test.py`
   asserts that a tooling release moves *zero* contour flags. It failed immediately:
   every frozen band was written against `CONTOUR_REVISION`, which is derived from the
   **behavior** axis. At an unregistered stamp (2.45) behavior resolves to the newest
   registered feature (2.44), so `CONTOUR_REVISION == (2, 44)` would have re-enabled the
   `false_completion_claim` best-of-2 trigger — a trigger measured **UNMEASURED** and
   deliberately not adopted at 2.44 — inside every future arm. All ten frozen bands now
   compare `STAMP_REVISION` (the parsed stamp). At registered stamps the two axes are equal,
   so no published arm's behavior changes; the fix only closes the tooling-release hole.
   Why it happened: the reserved tooling band (2.3-2.6, 2.8) predates this pattern, so
   nobody had ever stamped an *unregistered* revision above a registered feature.
4. **Every published arm was re-scored under the new stack** (`scripts/rescore_corpus_v62.py`
   → `benchmarks/hard/v6-results/rescore-v62/CORPUS-V62.md`, per-cell CSV
   `CORPUS-CELLS-V62.csv`): 8 476 replayable cells over 127 published answer files.
   Contract v6.1 vs v6.2 on the same bank: **0 disagreements** — the additive claim is
   measured, not asserted. Bank v6.1 → v6.2 gold correction: **83 wins, 0 losses**
   (`A-ex6-03` 51, `C-ex6-02` 32); strict total on the replayable set 6 912 → 6 995.
   Not replayable offline and reported as such: 1 380 category-E cells (need the docker
   battery), 675 loop-D cells (those arms never stored `_loop_rows` — a protocol gap in the
   old arms, now required by the runner), 3 genuinely empty answers.
5. **`versions/MEASUREMENT-STACK.md` (+ JSON)** now names, for every element and every run
   directory, the bank version + sha16, scorer contract + module hashes, seed protocol,
   contour stamp vs behavior, harness commit and energy windows. Regenerated by script, never
   retyped.

## What this changes for future runs

- A results directory published without a `stack` block is refused; a table that cannot name
  its bank sha16 and contract version is invalid by definition.
- A correction to any scoring byte is a **new** contract version plus a re-score of every
  published arm. Published bytes stay immutable.
- Any future tooling release must pass the "zero flag movement" assertion in gate_v49, so the
  stamp/behavior axis mistake cannot be repeated silently.
- The next measurement step is the v6.2 workspace + four-arm cadence on bank v6.2
  (`3c866ea7daae611c`); v6.1 and v6.2 numbers never share a column.

## Cost

Zero GPU minutes: offline re-score of stored answer bytes plus contract tests. No arm was
launched by this decision.
